🏗️ Chain99 Architecture & Internal Lifecycle
EVM Specification

Chain99 is an independent, sovereign Layer-1 blockchain built on top of the production-tested Go-Ethereum (Geth) client codebase. Here is how each component works in this system:

1. Starting Point
Independent Genesis
geth/genesis.json defines the chain genesis state: Chain ID 9999, 0 hardfork activation block heights, 30M gas limit, and 1,000,000 pre-funded C99 coins allocated to the dev validator account.
2. Consensus Mechanism
Clique PoA (EIP-225)
Instead of energy-intensive Proof of Work or complex multi-client Proof of Stake, Clique PoA uses cryptography-signed headers. The authorized sealer wallet signs and commits a new block every 2 seconds on the clock.
3. State & Storage
Merkle Patricia Trie
All account balances, contract code, and contract storage slots (like value in Storage.sol) are cryptographically stored in LevelDB on disk under data/node1/geth/chaindata.
4. RPC Gateway
JSON-RPC 2.0 (:8545)
Geth exposes the standard HTTP interface providing eth, web3, net, and txpool namespaces. Any standard tool (MetaMask, Ethers.js, Foundry, Remix) connects seamlessly.
5. P2P Layer
DevP2P Networking
Nodes communicate over port 30303. Node 2 (scripts/start-node2.sh) connects via Node 1's cryptographic enode URL to sync blocks and broadcast transactions in a decentralized topology.
6. Client Interface
This Dashboard
Connects directly to the RPC endpoint to provide real-time block streaming, automatic wallet configuration, contract deployment, and native token faucet operations.
